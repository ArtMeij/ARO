## Design decisions
1. **Scope = resource module only.** The VNet, subnets, operator identities and their role assignments, and the ARO RP's Network Contributor role are **not** created by the module. They now live in the test `dependencies.bicep`. The parameters this removed from the old attempt: `existingVirtualNetwork`, `virtualNetworkName`, `virtualNetworkResourceId`, `rpObjectId` and the commented-out VNet module.
2. **Identity model.** If `managedIdentities.userAssignedResourceIds` is set, the cluster is a managed/workload-identity cluster: `identity.type = 'UserAssigned'`, `platformWorkloadIdentityProfile` is sent, and `servicePrincipalProfile` is null. Otherwise it falls back to `servicePrincipalProfile` (a typed `{clientId, @secure clientSecret}`). Only the secret is secure; the client ID is not.
3. **Create-only properties.** `clusterProfile.version` and `clusterProfile.resourceGroupId` use `this.exists() ? this.existingResource()!.properties... : <param>`. This keeps redeploys from failing after an in-cluster upgrade, and it compiles without any experimental flag.
4. **Managed RG.** The `clusterResourceGroupName` param defaults to `aro-<name>`, and the module builds the RG ID from the current subscription. The old `resourceGroupId` param is replaced.
5. **Domain.** Defaults to `take('a${uniqueString(resourceGroup().id, name)}', 8)`.
6. **Networking defaults.** `outboundType` defaults to `Loadbalancer` (the API default; the old attempt used `UserDefinedRouting`). `loadBalancerProfile` is only sent when the outbound type is `Loadbalancer` **and** `managedOutboundIpCount` is set. API server and ingress default to `Private`. Pod CIDR is `10.128.0.0/14`, service CIDR `172.30.0.0/16`.
7. **Workers.** `workerProfiles` is limited to `@maxLength(1)`, because ARO accepts one worker profile at creation and extra pools are made in-cluster as MachineSets. Defaults: name `worker`, `Standard_D4s_v5`, 3 nodes, 128 GB disk.
8. **Masters.** `masterVmSize` defaults to `Standard_D8s_v5`.
9. **Removed:** `provisioningState` (read-only), the identity-creation experiments, and the Hosted Control Plane roles from `builtInRoleNames`. The roles left are Owner, Contributor, Reader, RBAC Administrator and User Access Administrator.
10. **No diagnostic settings** for now, since they're not believed to be supported on this resource type. **To verify.**
11. **Outputs:** `resourceId`, `name`, `resourceGroupName`, `location`, `clusterResourceGroupId`, `apiServerUrl`, `apiServerIp`, `consoleUrl`, `ingressIp` and `oidcIssuer` (nullable outputs use `string?`).
